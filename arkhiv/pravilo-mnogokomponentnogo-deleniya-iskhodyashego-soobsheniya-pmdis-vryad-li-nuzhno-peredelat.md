# Правило многокомпонентного деления исходящего сообщения (ПМДИС) - вряд ли нужно, переделать

При разделении длинных системных инструкций (промтов, ТЗ, спецификаций) на несколько сообщений для обхода лимитов контекста, технический анонс деления пишется строго один раз в самом начале первого фрагмента.

**Архитектура разделения:**

* **Первая часть:** Начинается с внешней служебной строки: «Я поделю следующее сообщение на \[Х], примени его, когда дам последнюю \[Х]-ую часть. Часть 1: \[Команда внедрения]». Далее открывается окно кода, куда помещается только первая часть контента.
* **Промежуточные части (со 2-й по предпоследнюю):** Содержат исключительно окно кода. Внутри этого окна кода первой строчкой идет команда позиционирования (например, «Внедри... сразу вслед за пунктом Х:»), а далее — чистый массив данных. Никакого внешнего текста, приветствий и триггеров «ожидания» за пределами окна кода быть не должно.
* **Финальная часть:** Аналогично промежуточным частям содержит только окно кода. В самом конце (внутри этого же окна кода) после основного массива данных ставится финальный триггер на запуск генерации итогового артефакта.
