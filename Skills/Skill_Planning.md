# 🧠 Навык планирования (/plan)

**Версия:** 1.0
**Назначение:** Универсальный навык для составления структурированных планов работ в любом проекте. Применим для всех ролей и моделей ИИ.

---

## 1. Принципы

1. **Artifact-Driven Decomposition** — каждая задача в плане ОБЯЗАНА иметь артефакт-результат. Задача без артефакта невалидна.
2. **Dependency-Aware Sequencing** — определение зависимостей между задачами. Критический путь — последовательность, где задержка любой задачи блокирует весь план. Параллелизация независимых задач.
3. **Dynamic Re-planning** — пересмотр плана после каждого выполненного этапа на основе полученных результатов. Если результат меняет условия — корректировать план ДО продолжения.
4. **Self-Reflection Before Execution** — самопроверка плана ДО начала исполнения: все ли задачи имеют артефакты, нет ли скрытых зависимостей, реалистичны ли объёмы.

---

## 2. Формат плана (для передачи ролям)

План должен быть оформлен так, чтобы его можно было скопировать и вставить как задание для роли. Каждый блок содержит:

- **Роль:** кому адресовано.
- **Задача:** что сделать (глагол + объект).
- **Артефакт:** что должно быть создано.
- **Критерий:** как проверить готовность (конкретные проверки).
- **Источник:** откуда брать данные.
- **Оценка:** время в часах/днях.
- **Приоритет:** P0 (критично) / P1 (важно) / P2 (желательно).

---

## 3. Шаблон блока для роли

```
### Роль: [/префикс]
**Задача:** [описание]
**Артефакт:** [имя файла/документа]
**Критерий:** [условие готовности]
**Источник:** [ссылка на документ/данные]
```

---

## 4. Правила применения

- Навык активируется по команде `/plan` или по явному запросу пользователя.
- План создаётся **только для текущих шагов**, а не для всего проекта (чтобы избежать перегруженности).
- План передаётся ролям в виде блоков для копирования.
- Остальные шаги выдаются после завершения текущих.

---

## 5. Пример использования

**Запрос:** «Составь план для разработки прототипа игры».

**Ответ (с применением навыка):**

```
### Шаг 1: Анализ референсов
### Роль: /reverse
**Задача:** Провести деконструкцию игры-референса (Core Loop, экономика, механики).
**Артефакт:** Deconstruct.md
**Критерий:** Документ содержит Core Loop, экономику, математику, паттерны.
**Источник:** Видео геймплея, скриншоты, документация.

### Шаг 2: Проектирование ГДД
### Роль: /gdd
**Задача:** Разработать Game Design Document на основе деконстракта.
**Артефакт:** GDD.md
**Критерий:** ГДД содержит механики, баланс, экономику, прогрессию.
**Источник:** Deconstruct.md, требования заказчика.
```

---

## 6. Примечание

Навык является самостоятельным и может использоваться в любом контексте, независимо от роли или модели ИИ. Он дополняет существующие системные настройки, но не заменяет их.
